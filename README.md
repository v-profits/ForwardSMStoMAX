# Объединение SMS в одно сообщение

Скопируйте папку `app` из `ForwardSMStoMAX` в корень проекта с заменой (изменён один файл: `sms/SMSReceiver.kt`).

## Как теперь работает
- Первое пришедшее SMS открывает **окно 30 секунд**. Все SMS, обработанные за это время, не уходят сразу.
- По истечении окна сообщения **группируются по получателю** (чат + ID Instance + токен) и уходят **одним сообщением**, между исходными сообщениями — **пустая строка**.
- В ту же отправку добавляются **сообщения этого получателя из очереди** (у них, как и раньше, строка `🔄 [дата время]`).
- Если SMS одно и очереди нет — сообщение выглядит как раньше.
- Если отправка не удалась: новые сообщения сохраняются в очередь по одному, у старых растёт счётчик попыток.
- Фоновая обработка очереди (каждые 10 мин) тоже объединяет сообщения одного получателя в одно, пауза 30 с остаётся только между разными пакетами.
- Слишком длинный пакет (> 15 000 символов) делится на несколько сообщений.
- Если часть длинного SMS ещё собирается на момент закрытия окна, закрытие откладывается (до +10 с).

## Журнал
Новый этап **ПАКЕТ**: «Добавлено в пакет для чата … (сообщений в пакете: N)». В записи ОТПРАВКА указано «в пакете сообщений: N» и «[из очереди]».

## Важно
- Сообщения ждут окно в памяти: если система убьёт процесс в эти 30 с, они пропадут (в журнале будет ПРИЁМ и ПАКЕТ без ОТПРАВКА). Задержка доставки теперь до ~30 с.
- Время окна — константа `BATCH_WINDOW_MS` в начале `SMSReceiver.kt`.
